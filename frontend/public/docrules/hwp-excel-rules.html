문서 배포 규칙 · 폐쇄망 실무

한글·엑셀 깨짐 방지 규칙집

내 PC에서 멀쩡한 문서가 상대 PC에서 페이지가 늘고 글자가 겹치는 원인은 거의 언제나 문서 밖 환경이다 —
글꼴, 프린터, 버전. 문서를 만들 때 이 규칙을 지키면 그 변수가 대부분 사라진다.

필수 어기면 사고 남 권장 지키면 사고 확률 크게 낮음 선택 상황 따라

0. 대원칙

규칙 스물아홉 개를 다 외울 필요 없다. 아래 흐름만 지키면 사고의 8할이 사라진다.

받는 사람이 이 문서를 편집할 이유가 있나? 없다 → PDF만 배포 있다 → 원본 + 아래 규칙 전부
편집이 필요해도 보고·열람용 사본은 PDF를 함께 준다 레이아웃 기준본
PDF는 글꼴 포함(임베딩)으로 저장한다 임베딩 없으면 PDF도 깨짐
CORE-01필수

레이아웃을 지켜야 하는 순간, 답은 항상 PDF다

HWP와 XLSX는 재조판(reflow) 포맷이다. 여는 PC의 글꼴·프린터·버전에 따라 매번 다시 계산된다.
PDF는 고정 포맷이라 계산이 끝나 있다.
편집 필요가 없는 문서를 원본으로 돌리는 건 이유 없이 사고 위험만 떠안는 것.

1. 한글(HWP)

한글 깨짐의 1순위 원인은 버전이 아니라 글꼴 대체다.
문서가 쓴 글꼴이 상대 PC에 없으면 한글이 다른 글꼴을 끼워 넣고, 글자 폭이 달라지고,
줄바꿈 위치가 밀리고, 페이지가 늘어난다.

글꼴 · 글자 모양

HWP-01필수

안전 글꼴 목록 안에서만 고른다

"어디에나 설치돼 있다"가 보장되는 글꼴만 쓴다. 예쁜 글꼴은 배포 문서에서 부채다.

구분글꼴근거
안전함초롬바탕 / 함초롬돋움한컴오피스 설치 시 동봉
안전맑은 고딕 / 굴림 / 바탕 / 돋움 / 궁서윈도우 기본 탑재
위험나눔 계열, 프리텐다드, 노토 산스 KR개별 설치 필요 — 없는 PC 많음
위험한컴 상위 패키지 전용 글꼴같은 한글이라도 에디션 따라 없음
위험기관 전용 / 구매 글꼴외부 배포 시 전부 대체됨 + 라이선스 문제
HWP-02필수

한글·영문·한자·기호 글꼴을 따로 확인한다

한글의 글자 모양은 언어별로 글꼴이 따로 지정된다.
한글만 바꾸고 영문을 놔두면 숫자·영문·괄호만 다른 글꼴로 나가서,
본인 PC에선 안 보이던 폭 차이가 상대 PC에서 터진다.

  • 글자 모양(Alt+L) → 언어별 설정에서 한글·영문·한자·기호를 같은 글꼴로 통일
HWP-03필수

자간 0, 장평 100%를 벗어나지 않는다

글자가 겹쳐 보이는 현상의 직접 원인이다.
자간을 음수로 조여둔 문단에서 글꼴이 폭 넓은 글꼴로 대체되면 글자끼리 파고든다.
"한 줄에 억지로 넣으려고" 자간을 줄이는 습관이 가장 위험하다.

  • 줄이 넘치면 자간이 아니라 문장을 줄이거나 글자 크기를 내린다
  • 표 안에서 특히 자주 발생 — 셀 폭 맞추려고 자간 조절 금지
HWP-04권장

글자 크기는 정수 pt로만

10.5pt 같은 소수점 크기는 버전·DPI에 따라 반올림이 갈리면서 줄 높이가 미세하게 달라진다.
한 페이지에 40줄이면 그 미세 차이가 한 줄 밀림으로 누적된다.

HWP-05권장

글꼴 포함하여 저장

안전 목록 밖 글꼴을 반드시 써야 한다면 문서에 글꼴을 심어 보낸다.
파일이 커지지만 대체를 원천 차단한다.
파일 → 문서 정보 / 저장 설정에서 글꼴 포함 옵션을 켜고,
그 글꼴의 라이선스가 재배포를 허용하는지 먼저 확인한다.

편집용지 · 문단 · 줄바꿈

HWP-06필수

편집용지를 명시적으로 설정한다

버전별 기본 여백이 다르다. F7로 용지 종류·방향·여백을 손으로 지정해 저장하면
그 값이 문서에 박혀서 어느 PC에서 열어도 같다.
손대지 않으면 여는 쪽 기본값을 따라갈 여지가 남는다.

  • 용지 A4, 방향 명시
  • 위·아래·왼쪽·오른쪽·머리말·꼬리말 전부 숫자 확인
  • 제본 여백은 0인지 확인 — 0이 아니면 좌우가 비대칭으로 밀린다
  • 구체적 수치는 소속 기관 공문서 규정을 따른다. 기관마다 다르니 임의 값을 쓰지 않는다
HWP-07필수

빈 줄로 페이지를 넘기지 않는다

엔터를 열 번 쳐서 다음 장으로 넘긴 문서는, 글꼴이 한 번만 대체돼도 그 열 줄이 밀려서
빈 페이지가 생기거나 제목이 앞장 끝에 매달린다.
"페이지가 하나 더 생긴다"의 가장 흔한 원인.

  • 페이지 넘김 → 쪽 나누기 Ctrl+Enter
  • 문단 간격 → 문단 모양의 위·아래 간격
  • 들여쓰기·정렬 → 탭 또는 문단 들여쓰기 (스페이스 반복 금지)
HWP-08권장

제목이 혼자 떨어지지 않게 문단 보호를 건다

문단 모양 → 다음 문단과 함께 / 문단 보호.
줄이 밀려도 제목과 본문 첫 줄이 갈라지지 않는다. 밀림 자체를 못 막아도 보기 흉한 결과는 막는다.

HWP-09선택

줄간격은 조직 규정 우선, 없으면 고정값(pt)

줄간격 % 지정은 글꼴 메트릭에 비례해 계산되므로,
글꼴이 대체되면 실제 줄 높이가 함께 변한다. 고정값(pt)은 글꼴과 무관하게 일정하다.
다만 공문서 규정이 160% 등 %를 명시하면 규정이 우선.

표 · 개체

HWP-10필수

표 너비를 본문 폭에 꽉 채우지 않는다

본문 폭에 딱 맞춘 표는 글꼴이 조금만 넓어져도 마지막 열이 밀려 나가거나
셀 안 텍스트가 한 줄 더 늘어나고, 그만큼 행 높이가 커져 페이지가 넘친다.
좌우 1~2mm 여유를 남긴다.

HWP-11권장

셀 여백을 명시하고, 표 제목 줄 반복을 켠다

  • 셀 여백 기본값에 기대지 않고 표 속성에서 값을 지정한다
  • 표가 페이지를 걸칠 수 있으면 제목 줄 반복을 켠다 — 머리행 없는 표 조각을 막는다
  • 행 높이가 '자동'이면 글꼴 대체 시 높이가 커진다. 중요한 표는 최소 높이를 지정한다
HWP-12필수

그림은 문서에 포함해 저장한다

"연결(링크)"로 넣은 그림은 상대 PC에 원본 경로가 없어 빈 상자로 나온다. 넣을 때 포함 옵션을 확인한다.

HWP-13권장

개체 배치는 '글자처럼 취급' 또는 '쪽 고정' 하나로 통일

  • 글자처럼 취급 — 본문과 함께 흐른다. 본문이 밀리면 그림도 같이 밀려 결과가 예측된다
  • 쪽 고정 — 페이지의 특정 위치에 못박힌다. 배경·로고에 적합
  • 어울림 / 자리 차지 — 주변 본문 흐름과 상호작용해 밀림이 가장 예측하기 어렵다

저장 · 배포

HWP-14권장

편집본은 hwpx, 배포본은 PDF

.hwpx는 ZIP+XML 구조라 부분 손상 복구와 외부 검사가 되고 버전 간 호환도 낫다.
.hwp는 바이너리라 깨지면 통째로 잃는다.
하위 버전 사용자가 확실히 있으면 그쪽이 열 수 있는 포맷으로 별도 저장해 함께 준다.

HWP-15필수

배포 전 다른 PC에서 최소 1회 연다

규칙을 다 지켜도 이 한 번을 대체하지 못한다.
확인할 것은 셋 — 총 페이지 수, 표가 페이지를 걸치는지, 인쇄 미리보기(화면과 인쇄는 다르다).
가능하면 한글 버전이 다른 PC로 확인한다.

2. 엑셀

엑셀은 화면상 데이터가 멀쩡해 보여서 안전하다고 착각하기 쉽다.
실제 사고는 인쇄 결과와 수식 호환에서 난다.

글꼴 · 행/열

XLS-01필수

열 너비는 글꼴 폭에 종속된다

엑셀 열 너비 단위는 mm가 아니라 기본 글꼴의 문자 폭이다.
상대 PC 기본 글꼴이 다르면 같은 너비 값이 다른 실제 폭이 되고,
숫자 열이 #####로 바뀌거나 텍스트가 잘린다.

  • 통합 문서 기본 글꼴을 맑은 고딕 11pt(윈도우 엑셀 기본)에서 벗어나게 바꾸지 않는다
  • 바꿔야 하면 열 너비에 여유를 크게 준다
XLS-02권장

행 높이 '자동'은 인쇄 페이지 수를 바꾼다

자동 맞춤 행 높이는 여는 PC의 글꼴·DPI로 재계산된다.
인쇄 페이지 수를 지켜야 하는 양식은 행 높이를 숫자로 고정한다.

XLS-03권장

셀 병합을 최소화한다

병합 셀은 정렬·필터·복사·수식 참조를 전부 깨뜨린다.
받는 사람이 데이터를 가공하려 할 때 첫 번째로 부딪히는 벽이다.
모양이 목적이면 선택 영역의 가운데로 맞춤을 쓴다.

인쇄

XLS-04필수

인쇄 영역·배율·반복 행을 명시한다

지정하지 않으면 엑셀이 알아서 자르고, 그 판단은 PC마다 다르다.

  • 페이지 레이아웃 → 인쇄 영역 설정
  • 배율은 "자동 맞춤"이 아니라 숫자 배율로 고정한다. 자동은 PC마다 다르게 나온다
  • 여러 장이면 인쇄 제목 → 반복할 행에 머리행을 지정한다
  • 페이지 나누기 미리보기로 실제 잘리는 위치를 확인한다
XLS-05권장

필터·숨긴 행이 걸린 채로 저장하지 않는다

받는 사람은 필터가 걸린 줄 모르고 데이터 일부만 보고 판단한다.
실무 사고 중 파급이 가장 크다. 저장 전 필터를 풀고 숨긴 행·열을 확인한다.

수식 · 데이터

XLS-06필수

구버전에서 깨지는 함수를 쓰지 않는다

상대 엑셀이 2016 이하면 아래 함수는 #NAME?로 나온다. 값까지 같이 날아간다.

쓰면 위험필요 버전대체
XLOOKUPM365 / 2021+INDEX + MATCH
LET, LAMBDAM365 / 2021+보조 열로 분해
동적 배열 (스필)M365 / 2021+구버전에서 @ 붙어 깨짐
TEXTJOIN, IFS, CONCAT2019+& 연결, 중첩 IF
MAXIFS, MINIFS2019+배열 없는 대안 구성
XLS-07필수

외부 파일 참조를 끊고 보낸다

다른 통합 문서를 참조하는 수식은 상대 PC에서 #REF!가 되거나
"연결 업데이트" 경고창을 띄운다.
경로에 내부 서버명·사용자명이 노출되는 부수 문제도 있다.

  • 배포 전 데이터 → 연결 편집에서 외부 연결을 확인하고 값으로 변환한다
  • 같은 이유로 절대 경로를 수식에 박지 않는다
XLS-08권장

휘발성 함수는 배포본에서 뺀다

NOW() TODAY() RAND() OFFSET() INDIRECT()는 파일을 열 때마다 재계산된다.
작성일을 박아 보낸 문서가 상대가 여는 날짜로 바뀐다. 확정 값은 값 붙여넣기로 고정한다.

XLS-09필수

날짜는 날짜 값으로, 표기는 서식으로

날짜를 텍스트로 입력하면 정렬·계산이 어긋나고, 지역 설정이 다른 PC에서 월과 일이 뒤집힌다.
셀에는 날짜 값을 넣고 표시 형식으로 yyyy-mm-dd를 지정한다.
Mac에서 만든 파일은 1904 날짜 체계일 수 있어 4년 차이가 나기도 한다.

XLS-10권장

숫자를 텍스트로 저장하지 않는다

셀 왼쪽 정렬 + 초록 삼각형이면 텍스트다. SUM에 안 잡히고 VLOOKUP이 못 찾는다.
받는 사람이 원인을 못 찾고 시간을 태운다.

저장 · 배포

XLS-11권장

호환성 검사와 문서 검사를 돌린다

  • 파일 → 정보 → 문제 확인 → 호환성 검사 — 구버전에서 깨질 요소를 엑셀이 알려준다
  • 문서 검사 — 메타데이터, 작성자명, 숨긴 시트·행, 메모를 제거한다
  • 시트명은 31자 이내, \ / : * ? [ ] 금지
XLS-12선택

매크로(xlsm)는 폐쇄망에서 차단될 수 있다

보안 정책상 매크로가 막힌 환경이면 xlsm은 열려도 동작하지 않는다.
매크로 없이 되는 방식을 먼저 택하고, 꼭 필요하면 매크로 없이도 값은 보이도록 설계한다.

3. 환경 진단

문서 내부 설정(여백·문단모양·자간)은 문서에 박혀 있어 PC가 바뀌어도 안 변한다.
대조할 대상은 문서가 아니라 PC 환경이다.

ENV-01권장

사고 나면 양쪽 PC 환경을 5분 안에 대조한다

추가 설치 없이 윈도우 내장 PowerShell만으로 뽑힌다.
양쪽에서 돌려 글꼴목록.txt를 비교하면 대체된 글꼴이 바로 나온다. 

# 설치 글꼴 목록 (시스템 + 사용자)
Get-ChildItem C:\Windows\Fonts, "$env:LOCALAPPDATA\Microsoft\Windows\Fonts" -ErrorAction SilentlyContinue |
  Select-Object -ExpandProperty Name | Sort-Object | Out-File 글꼴목록.txt -Encoding utf8

# 기본 프린터와 드라이버
Get-CimInstance Win32_Printer | Where-Object { $_.Default } | Select-Object Name, DriverName

# 설치된 한컴 제품
Get-ItemProperty "HKLM:\SOFTWARE\HNC\*" -ErrorAction SilentlyContinue | Select-Object PSChildName

# 두 PC 결과 비교
Compare-Object (Get-Content a.txt) (Get-Content b.txt)

문서가 쓴 글꼴이 한쪽에만 있으면 범인 확정.

4. 케이스북

한컴 도움말은 렌더링 엔진 변경을 이 수준으로 기술하지 않는다.
공식 문서 대조보다 겪은 사례를 축적하는 쪽이 정확하다. 겪을 때마다 항목을 늘린다.

CASE-01 · 한글 2024에서 만든 문서가 상대 PC에서 페이지 1장 증가

증상

빈 줄로 페이지를 넘긴 구간이 있으면 증폭됨. 기본 프린터 차이도 기여 가능
확인
ENV-01로 글꼴 목록 대조 — 문서 사용 글꼴이 상대 PC에 있는지

HWP-01 안전 글꼴 / HWP-07 쪽 나누기 / 배포는 PDF

CASE-02 · 특정 글자 1개가 겹쳐 보임

증상
