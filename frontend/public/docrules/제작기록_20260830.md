# hwp-excel-rules.html 제작 기록

작성 2026-08-30. `hwp-excel-rules.html` 과 `validate_doc.js` 가 어떤 근거로 만들어졌는지,
중간에 뭘 틀렸고 어떻게 잡았는지 남긴다.

## 1. 발단

폐쇄망에서 문서 작업하는 쪽이 "AI 활용이 불가능한 환경이라 답이 없다"고 함.
반박하는 과정에서 실제 겪은 사고 두 건이 나옴.

- 한/글 2024로 만든 문서를 2018 쓰는 PC에서 열었더니 **페이지가 1장 늘어남**
- **글자 하나가 겹쳐 보이는** 케이스 1건
- 당시 조치는 PDF로 출력해 배포. 받는 담당자가 편집할 이유가 없었음

초기 가설은 "버전 차이"였다. 이 가설이 맞는지 확인하는 것이 작업의 출발점.

## 3. 근거 수집 — 한컴 공식 도움말 미러링

### 3.1 버전 매핑 실측

한컴 도움말은 제품·버전별 프로젝트 ID로 나뉜다. 추측하지 않고 응답 title 로 확인.

| 폴더 | 프로젝트 ID | 제품 |
|---|---|---|
| `2018/` | `hoffice100` | 한컴오피스 2018 한/글 |
| `2020/` | `hoffice110` | 한컴오피스 2020 한/글 |
| `2022/` | `hoffice120` | 한컴오피스 2022 한/글 |
| `2024/` | `hoffice130` | 한컴오피스 2024 한/글 |
| `hpdf/` | `Hpdf` | 한/PDF |

이 외에 `HCell`(한/셀) `HShow`(한/쇼) `Hword`(한/워드) 존재 확인. 이번엔 안 받음.

한컴은 사용설명서 PDF 를 공개 배포하지 않는다. **공식 문서는 이 웹 도움말이 전부다.**

### 3.2 크롤러 — 1차 실패와 재작성

wget·python 둘 다 없어서 curl + bash 로 직접 작성.

**1차** — 페이지마다 curl·sed·grep 프로세스를 새로 띄우는 축차 BFS.
측정 결과 **0.39 pages/sec, 버전당 125분, 4버전 8시간.** 그대로 두면 밤새 돌 뻔했다.

원인 둘.
- 윈도우에서 프로세스 생성 비용이 큼
- `sed -i '1d'` 로 큐 파일을 매 반복 통째로 다시 씀

**2차** — 레벨 단위 병렬 BFS 로 재작성.
한 레벨의 URL 을 curl 설정 파일로 모아 `--parallel --parallel-max 10` 으로 일괄 요청.
링크 추출과 `../` 경로 정규화는 awk 한 프로세스(`extract_links.awk`)로 처리.

**결과 4.44 pages/sec — 11배.** 4버전 3,598페이지를 16분에 수집.

### 3.3 한/PDF 수집 중 만난 경로 버그

`run_hpdf.sh` 가 0페이지로 실패. 에러는 `wc -c < "$dest"` 줄에서 났지만 진짜 원인은 다른 데 있었다.

`ROOT="$(cd ... && pwd)"` 가 msys 경로(`/c/workspace/...`)를 만들었고,
**curl 은 네이티브 윈도우 바이너리라 그 형식을 못 읽는다.**
기존 `run_all.sh` 는 `C:/...` 로 하드코딩돼 있어서 우연히 안 걸렸던 것.

`pwd -W` 로 변환해 넘기도록 `crawl.sh` 수정. 제품 인자와 시드 자동 탐지도 함께 추가.

```bash
bash _meta/crawl.sh <hofficeNNN> <출력경로> [최대] [제품]
# 시드는 각 제품 projectdata.js 의 DEFAULT_TOPIC 에서 자동으로 알아낸다
```

### 3.4 버전 대조 — to_text 버그와 오판

`diff_versions.sh` 로 2018 ↔ 2024 를 대조. **1차 결과가 "861개 동일 / 4개 변경"** 으로 나왔다.
거의 안 바뀌었다는 뜻이라 결론까지 그렇게 보고했다.

**틀렸다.** 본문 텍스트 추출 함수가 이랬다.

```bash
sed -e ':a' -e 'N' -e '$!ba' -e 's/<script[^>]*>.*<\/script>//gI' ...
```

파일 전체를 패턴 공간에 슬럽한 뒤 지우는데, `.*` 가 탐욕적이라
**첫 `<script>` 부터 마지막 `</script>` 까지 = 본문 전체가 날아갔다.**
빈 텍스트끼리 비교하니 당연히 "동일"이 나온 것.

줄 범위 삭제 방식으로 교체.

```bash
sed -e '/<[Ss][Cc][Rr][Ii][Pp][Tt]/,/<\/[Ss][Cc][Rr][Ii][Pp][Tt]>/d' ...
```

**재실측 332 동일 / 533 변경.** 앞서 보고한 수치는 폐기.

발견 경로는 `cmp` 였다. 스크립트는 "동일"이라는데 바이트 비교로는 다르다고 나와서 파봤더니
자간 페이지 차이가 `"다단 편집"` → `"단 편집"` 세 군데. 텍스트 diff 가 이걸 놓칠 리 없는데
놓쳤다는 게 단서가 됐다.

## 4. 대조 결과 — 초기 가설 반증

2018 ↔ 2024 도움말 3,598페이지 전수 대조.

| 항목 | 결과 |
|---|---|
| 2018 페이지 | 918 |
| 2024 페이지 | 887 |
| 본문 동일 | 332 |
| 본문 변경 | 533 |
| 2018 에만 있는 페이지 | 55 |
| 2024 에만 있는 페이지 | 22 |

**줄바꿈 알고리즘·글꼴 대체 규칙·렌더링 엔진 변경에 관한 서술은 한 줄도 없었다.**
변경 폭 상위는 전부 차트 관련(`chart(axis)` 2,950줄 등)이고, 나머지는 용어 개명과 문구 다듬기.

즉 **"버전 차이 때문"이라는 초기 가설은 근거를 찾지 못했다.**
페이지 증가와 글자 겹침은 버전이 아니라 **PC 환경(글꼴 설치 여부) 차이**로 설명되고,
같은 버전끼리도 발생한다.

### 실제로 확인된 2018 → 2024 차이 넷

1. **「주의 글꼴 알림」 신규** — 2024 에만 있음. 한컴이 안전 글꼴 목록을 명시한 근거가 여기서 나옴
2. **표 셀 속성 설명 대거 추가** — [제목 셀] [크기 고정] [한 줄로 입력] [셀 보호]
3. **PDF 저장 옵션 확장** — 변환 범위·그림 품질·암호·권한
4. **하위 호환 항목 제거** — `문서 호환성` `97 버전으로 저장` `한글 2007 문서 열기` 도움말이 사라짐

배포에 직접 걸리는 것은 4번뿐이다.

## 6. 검증 도구 확보

"문서 처리를 검증할 도구를 먼저 확보하라"는 지시에 따라 규칙집 수정보다 앞서 진행.

### 6.1 조사

설치 위치는 `C:/workspace/node_modules`. 저장소 밖, 기존 puppeteer 와 같은 자리.

### 6.2 포맷 구조 실측

**hwpx** — 실파일을 열어 확인.

```
Contents/header.xml    fontfaces, charProperties
Contents/section0.xml  pagePr, margin, 본문
```

```xml
<hh:font id="0" face="굴림" type="TTF" isEmbedded="0">
<hh:spacing hangul="-5" latin="-5" .../>   자간
<hh:ratio   hangul="95" latin="95" .../>   장평
<hp:pagePr landscape="WIDELY" width="59528" height="84188" gutterType="LEFT_ONLY">
<hp:margin header="0" footer="0" gutter="0" left="5669" right="5669" .../>
```

HWPUNIT 은 1인치 = 7200. `5669 / 7200 × 25.4 = 20.0mm`, `59528 → 210mm` (A4 확인).

**hwp** — hwp.js 가 노출하는 구조.

```
info.fontFaces[]    {name, alternative, default}  ← 7개 언어 × 18개 배열
info.charShapes[]   fontId[7] fontScale[7](장평) fontSpacing[7](자간) fontBaseSize
sections[0]         width height padding* orientation bookBindingMethod
info.binData        포함된 이미지
```

`fontFaces` 가 언어 그룹이 이어붙은 배열이라 `faces[언어 × 그룹크기 + fontId[언어]]` 로 역참조.

### 6.3 validate_doc.js

규칙 번호를 그대로 출력하는 판정기. FAIL / WARN / PASS / INFO 4등급.

안전 글꼴 목록의 근거는 한컴 「주의 글꼴 알림」 면제 목록을 그대로 가져왔다.

## 8. 점검표 개편

### 8.1 문서별 분할

한 덩어리였던 배포 전 점검을 셋으로 나눔. 한글만 보낼 때 엑셀 항목을 안 봐도 된다.

| 그룹 | 항목 |
|---|---|
| 공통 · 배포 방식 결정 | 4 |
| 한/글 배포 전 점검 | 17 |
| 엑셀 배포 전 점검 | 16 |

그룹별 독립 카운터, 저장 키도 분리. 앱바는 총합(37) 표시.

### 8.2 체크박스와 라벨 분리

| 클릭 지점 | 동작 |
|---|---|
| 왼쪽 36×36 정사각형 | 체크만 토글 |
| 항목 글씨 | 처리 방법만 펼침. 체크 상태 안 바뀜 |

37항목 중 **36개에 처리 방법 작성.** 메뉴 경로 → 순서 → 함정 → 왜(각주) 구조.
설명을 안 붙인 하나는 `CORE-01` — 사람에게 물어봐야 하는 판단이라 절차가 없다.

## 9. DRM 제약 반영

`validate_doc.js` 는 실행 스크립트라 폐쇄망에서 반입 절차와 DRM 해제를 거쳐야 하고 Node 도 필요하다.
사실상 못 쓸 가능성이 높다는 지적을 받아 문서를 고쳤다.

## 12. 남은 것

- **단일 HTML 검증기** — `validate_doc.js` 로직을 HTML 한 파일로 옮기는 안.
  hwpx·xlsx 둘 다 ZIP 이라 브라우저 내장 `DecompressionStream('deflate-raw')` 로 처리 가능.
  설치·실행파일·Node 불필요하므로 DRM 문제를 우회한다. `.hwp` 바이너리만 못 읽는다
- **버전 차이 절** — 규칙별로 "버전 차이 때문 / PC 환경 차이 때문 / 작성 실수"를 분류한 표.
  지금은 케이스북에 "도움말에 렌더링 서술 없음"이라고만 적혀 있다
- **소요 표시** — 항목마다 `확인만` / `작업 필요` 뱃지. "처음 15분 → 이후 3분, 핵심은 셋" 안내
- 한/셀·한/쇼·한/워드 도움말은 안 받았다. `crawl.sh` 의 제품 인자만 바꾸면 받아진다

## 13. 검증하지 못한 것

- 시험 파일이 `.hwp` 1개, `.hwpx` 1개뿐이다. hwp.js 는 0.0.3 알파라 다른 파일에서 파싱이 깨질 수 있다
- **2018 에서 저장한 파일과 2024 에서 저장한 파일을 직접 비교하지 못했다.** PC 에 2018 저장본이 없다.
  포맷 규격상 같아야 한다는 근거로 말하는 것이지 실측이 아니다
- CASE-01·02 의 원인은 여전히 **추정**이다. 당시 양쪽 PC 의 글꼴 목록을 대조한 기록이 없다.
  같은 증상이 재발하면 `ENV-01` 로 실측해 케이스북을 갱신할 것
